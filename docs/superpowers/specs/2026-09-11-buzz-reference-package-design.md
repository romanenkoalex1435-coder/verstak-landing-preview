# Пакет «после Buzz-референса» — утверждённая схема

## Контекст

alexandr прислал запись экрана buzz.xyz. claude code разобрал её покадрово (`buzz media get` + `ffmpeg`), codex независимо разобрал shipped HTML/CSS/JS. Формула, которая реально создаёт впечатление у Buzz: **смело → спокойно → продукт → смело** — не набор мелких hover-эффектов, а режиссура нескольких крупных сцен. Полное обсуждение и утверждение — в канале Welcome, тред `ab12c767…`, 2026-09-11.

Прямо копировать нельзя: рой частиц/значков (пчелиная айдентика Buzz), гигантский размытый wordmark, кастомный курсор — это бренд Buzz, не универсальный приём.

## Утверждённая схема (alexandr подтвердил)

1. **Порядок секций:** hero → прототип → конструктор → работы → границы → процесс → о нас → FAQ → финальный CTA. «Границы» перенесены сразу после «Работ» (раньше стояли перед ними и сбивали разгон перед главной продуктовой сценой).
2. **Hero** — неподвижный читаемый оффер, маршрут «Заявка → Исполнитель → Выезд → Результат» проигрывается один раз при входе в вид. Уже реализовано в `hero-route` (`data-motion-decor`, стаггер через `initMotionScenes`) — без изменений.
3. **Конструктор** — сумма/срок меняются одометром вместо мгновенной подмены, у добавленного блока в стеке короткий settle. Новое: `animateNumber()` и `.sx-stack-row.is-settling` в `core.js`/`index.html`.
4. **«Работы» — главная sticky-сцена.** Дашборд (`.gallery-shell`) остаётся визуальным якорем на десктопе (`position:sticky` внутри `.works-scene`/`.works-scene-pin`, ≥961px), 3 кейса (индексы `[3, 1, 6]` в `D.cases`) сменяются по scroll-прогрессу через `initScrollScene()`. Смена кейса переиспользует существующий 180ms `is-changing` кроссфейд — отдельного «sheen»-механизма не вводили, он был бы избыточен. Ручное переключение (табы/стрелки/клавиатура) продолжает работать поверх скролл-состояния. Mobile (<961px) и `prefers-reduced-motion: reduce` отключают scrub полностью — секция остаётся обычной статичной галереей с табами, без инфляции высоты.
5. **Финал** — насыщенный тон градиента (`scroll-aura`) и завершённая маршрутная нить (`route-complete`, галочка) на `#request-cta`. Уже реализовано в прошлых коммитах (`ac02a19`, `4406a03`) — фактически удовлетворяет требование «вернуть мотив», отдельно ничего не добавляли.
6. **Микродеталь:** не добавляли отдельную — переиспользование существующего кроссфейда в п.4 закрывает требование «одна поддерживающая деталь, если сцена без неё выглядит незавершённой».

## Что сознательно не переносим

Частицы/значки, гигантский wordmark, кастомный курсор, 3D tilt/parallax, постоянные циклические анимации.

- Полный набор `tests/*.js` — 7/7 PASS до и после (один golden-тест ловил случайное совпадение имени функции `sync()` между новым сценарием и `ПРОТОТИП`-модулем — переименовано в `syncScene()`).
- Визуально через headless Chrome (Playwright + системный Chrome, `channel:'chrome'`): desktop 1440×900 (hero, constructor odometer mid-tween/settled, 4 точки scroll-прогресса sticky-сцены, finale), mobile 390×844 (`data-scrub` не выставляется, `style.height` пуст — секция ведёт себя как раньше), `reducedMotion:'reduce'` (то же самое — scrub выключен).
